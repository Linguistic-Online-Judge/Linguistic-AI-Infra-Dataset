# 校内外公开访问与发布计划

## 已确认目标与当前状态

老师已确认：正式网站应允许校内外访问，不限校内网络。
这表示访问入口需要面向互联网；提交评测、查看本人历史和教学管理继续遵守既有
登录及角色权限，不因此改成匿名操作。

当前已完成的是学校服务器上的开发实例：74项目录、70个可执行配置，18语言基础
任务覆盖和新增XPOS已运行验收。当前8090通过SSH转发访问，尚无已经验证的公网网址。
GitHub仓库是公开代码仓库，仓库公开与网站公开是两件事。

## 正式部署位置与访问路径

沿用学校的Qwen3.5-9B资源，网页和后端可由同源FastAPI服务提供，不要求额外购买
前端主机或更换框架。学校提供的公网网关也可以作为应用入口。

```text
任意校内外用户的浏览器
        │ HTTPS：学校确认的域名
        ▼
公网入口 / 反向代理（接收访问并转发给内部应用）
        ▼
正式应用：网页、登录、任务目录、提交与结果
        ├─ 正式数据库
        └─ 任务队列 → 受控执行器 → 学校Qwen3.5-9B
```

正式使用者不需要本机运行Python、下载仓库或建立SSH转发。数据库、Redis和模型
端口保持内部访问，只向公网提供网站所需入口。

**不能直接将当前`qwen_development`的8090端口映射到公网。** 它具有共享测试账号、
测试邮件收件箱和开发模式题目覆盖设置，设计用途是受控开发。
正式服务应使用生产组合和独立配置，并保留现有开发实例与历史数据。

## 需要学校或部署方提供的实际信息

| 信息 | 为什么需要 |
| --- | --- |
| 正式域名及归属 | 用户通过哪个固定网址访问；用于同源校验、Cookie和邮件链接 |
| 校外可达的入口 | 公网地址或学校网关怎样转发到应用，不能仅有校内私网地址 |
| HTTPS证书和代理维护方式 | 确认由学校还是项目部署方申请、配置和续期 |
| 长期进程运行方式 | 明确应用停止、服务器重启后由什么机制恢复，以及可用的管理权限 |
| 真实邮件投递配置 | 发送注册验证和密码重置邮件；凭据通过私有配置交付，不写入GitHub |

“允许所有人访问”已确定使用目标，但还不等于这些网络与运维条件已经配置完成。

## 正式服务需要完成的迁移工作

域名可后续确认。现已提供`config/production.example.json`和
`scripts/prepare_public_deployment.py`，可离线生成代理/应用/认证配置草稿及待补项报告。
具体参数、私有文件、检查命令和验证边界见[正式部署准备](PRODUCTION_PREPARATION.md)。
当前注册表通过静态模型配置检查，但70份合同均未满足现有正式公开受理条件；
准备工具据此保留待办，不修改任务状态。

1. **生产账户与真实投递**：使用`qwen_api`生产模式和受保护的`--auth-config-file`，
   配置正式域名对应的Cookie及邮件链接。开发共享账号和公开收件箱不进入正式实例。
   既有开发账号/测试成绩继续保留，正式账号和历史迁移需明确身份绑定。
2. **可公开任务清单**：按来源许可、归因和原文权利确认可开放的条目。当前draft
   覆盖设置只适用于开发，不能通过`--allow-draft-submissions`绕过生产约束。
3. **网络和代理**：配置正式HTTPS入口与精确可信代理。同源网页访问后端；不能将
   任意用户提供的转发地址直接当成真实客户端地址。
4. **执行与容量**：沿用固定模型和受控调度。当前内测串行执行，不因有70个合同就
   启动70个并发模型作业；等待期限和可支持人数按实际负载验证。
5. **运行与恢复**：验证进程监督、日志定位、当前数据库备份和恢复、发布回退。
   未确认旧推理终止时不得盲目重启或重投。

统一串行执行器和持久恢复入口现已实现，说明见[生产执行器](PRODUCTION_EXECUTOR.md)。
对应隔离故障测试与学校实际模型/服务验收分别记录；现有开发实例尚未切换。

## 公网发布验收

- 用实际校外网络访问正式域名，不依赖个人SSH转发。
- 用真实邮箱完成注册、验证、登录和密码重置，生产页面没有共享测试账号或收件箱。
- 完成受理、排队、评测、结果、本人提示词、历史和分区排行榜。
- 其他用户不能读取本人提示词，普通账号不能进入教学管理；管理员也不绕过本人范围。
- 验证声明规模下的等待与失败情况、重启恢复及隔离备份恢复。
- 运行版本与审核通过的Git提交/构件一致，再在README公布真正可访问的网址。

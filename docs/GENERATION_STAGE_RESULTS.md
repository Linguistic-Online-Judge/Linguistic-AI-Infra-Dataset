# 首词元与生成阶段测量（2026-09-20）

**结论：本轮德语依存请求的引擎推理时间有98.3%处于后续生成阶段，输入处理仅占约
1.7%。后续性能工作应集中在生成吞吐，而不是继续将主要精力放在输入缓存上。**
这是单并发、空闲服务下的小样本阶段测量，30人完整评测50秒目标仍未达到。

## 1. 采集方式

学校现有vLLM提供首词元、排队、预填充（处理输入并产生首个词元）、后续生成及总推理
时长的直方图计数和累计值，因此可以保持原非流式请求，逐请求读取指标前后差。
新增入口：`python -m linguistic_oj.generation_stages`。

- 原模型、原输入与输出协议、原生成设置及单并发均保留，无服务重启。
- 英语CHILDES词性标注、德语HDT依存，各取冻结清单前6样本、重复2遍，另各预热1次。
  实际共26次请求，正式统计各12次，预热单列。
- 相邻请求间隔5秒。每次发送前及归因前检查应用状态、模型进程归属/启动时间/参数摘要、
  在线提交计数和模型活动指标。检测到活动或状态变化即停止后续分配。
- 使用`GuardedQwenProvider`的持久请求前置记录；不因指标超时、归因失败或连接异常
  自动重发。连接终止未确认时保留恢复屏障。
- 必须只增加1次完成请求，各阶段直方图必须各增加1次，输入/输出词元总量必须与响应
  一致。拒绝计数回退、其他模型或引擎、重复指标、非有限值及阶段时长不一致。
  允许等待指标更新最多15秒；归因无效时保留已完成请求记录，不提供阶段结论。

这些检查不是全服务器独占预约，也不能阻止外部客户端在检查后发起请求。
本轮所有26次请求均通过归因检查，应用状态与提交计数保持稳定。

## 2. 阶段定义

已读取学校安装版本`vllm/v1/metrics/stats.py`核对语义：

| 报告指标 | 计时边界 |
| --- | --- |
| `time_to_first_token_seconds` | 服务端记录的请求到达至首词元产出观察；不是浏览器首字出现时间 |
| `request_queue_time_seconds` | 引擎首次入队至首次被调度 |
| `request_prefill_time_seconds` | 首次被调度至首词元事件 |
| `request_decode_time_seconds` | 首词元至最后词元事件 |
| `request_inference_time_seconds` | 首次被调度至最后词元事件，等于预填充加后续生成 |
| `e2e_request_latency_seconds` | 模型服务自身记录的请求总时延，不是网站端到端时延 |
| `client_request_seconds` | 实验客户端调用完整受保护provider的墙钟时间 |

引擎阶段间隔包含期间发生的抢占等等待，不是纯GPU内核运行时间。后续生成速率采用
`sum(输出词元数 - 1) / sum(后续生成秒数)`，不重复计算预填充阶段产生的首词元；
单词元输出不构造虚假的生成速率。这里的词元不等于中文字符或单词。

## 3. 真实结果

以下均排除预热，按每项任务12次正式请求计算：

| 指标 | 英语词性标注 | 德语依存分析 |
| --- | ---: | ---: |
| 平均服务端首词元时间 | 0.094151s | 0.176112s |
| 平均引擎排队时间 | 0.0000276s | 0.0000351s |
| 平均输入预填充时间 | 0.088568s | 0.166857s |
| 平均后续生成时间 | 0.290098s | 9.664343s |
| 平均引擎推理时间 | 0.378666s | 9.831201s |
| 平均模型服务请求总时延 | 0.384222s | 9.840503s |
| 平均实验客户端完整调用时间 | 0.494807s | 9.952586s |
| 平均输出词元数 | 15 | 470.833 |
| 后续生成速率（加权） | 48.26词元/s | 48.62词元/s |
| 后续生成占引擎推理时间 | 76.61% | 98.30% |

单并发下两种任务的后续生成速率接近，德语需要生成的答案明显更长。
在本轮德语工作量中，即使把预填充时间压到零、其他阶段不变，也只消除约1.7%的
引擎推理时间。这与上一轮前缀缓存命中后未观察到总请求提速的结果相符。

实验客户端时间比服务端请求时延平均多约0.111/0.112秒。差值包含客户端持久请求保护、
通信及响应处理等工作，尚未逐项分离，不能全部归因于网络或在线网站开销。

英语4/12、德语2/12输出存在格式错误；每个样本两次输出摘要一致。
模型调用完成不等于评分质量达标。格式错误请求仍属于实际消耗的模型工作量，
因此未从时间统计中删去。预热客户端耗时分别0.459秒和8.920秒，未混入正式平均值。

## 5. 适用范围与下一步

空闲时几乎没有排队，不代表30人同时提交时也没有排队；单请求48词元/s不是整卡
高并发吞吐上限。两次重复的6个样本也不能代表18语言全量数据。

后续优先检查批处理下的生成吞吐和执行内核耗时，结合质量重复性判断可采用的参数。
若进一步优化仍不足，再据完整工作量证据评估所需计算资源。当前测量尚不能证明
显存带宽饱和、某个具体内核是瓶颈，或给出必需显卡数量。

后续已在新的授权窗口完成固定工作量和短时内核追踪，见
[批处理与内核实测](BATCH_KERNEL_RESULTS.md)。两阶段证据分开记录，不把追踪开销
混入本页原始测量。

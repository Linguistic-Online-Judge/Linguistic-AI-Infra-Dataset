## 为什么没有更多

`scripts/build_v1_challenge_catalog.py`默认对18语言只构建UPOS，
`V1_SUPPLEMENTAL_CHALLENGES`固定添加中文分词、中文转写、德语XPOS和德语依存。
这是此前的配置/验收范围，不是数据或语言能力上限。

当前标准数据共有135180个样本，但需要完整标注、可见词形及任务校验合格才能进入
对应候选池。总句数不等于可用于每个任务的数量，也不等于已经建成的网站练习数量。

## 扩充目标与步骤

数据支持进一步审核的组合为：18×3基础任务＋16项XPOS＋5项转写＝**75个候选组合**。
这是按每种语言每类先建一项计算的候选范围，比当前22项多53项；不是已上线承诺。

1. **基础覆盖**：优先让每种语言都有分词、UPOS、依存三项。
2. **专用词性**：为16种已有数据的语言补齐XPOS；确认标签体系和与UPOS的实际区别。
3. **转写**：先补阿拉伯语、印地语、韩语、泰语，再审核其余非拉丁文字语言的标准与数据。
4. **教学深度**：在覆盖建立后按题材、长度或经审核的难度组织多个练习集，而不是仅
   修改随机种子制造看似很多的任务。

### 每个新任务的执行条件

- 来源、许可、原文可用性与标注质量；不能因有数据就跳过已有来源限制。
- 任务定义和样本输入必须匹配。当前分词输入来自`model_inputs.py`中拼接固定词元，
  是边界恢复式练习。扩展到其他语言时要说明与自然文本分词的差异，并处理多词词元、
  缩合词、空格和标点；若改用真实原文，应采用新合同和新版本，不改旧成绩的含义。
- 根据语言/树库提供正确说明、标签和模板，不能把德语STTS或中文拼音规则套给所有语言。
- 生成新的公开描述、私有清单、执行合同；审核全部样本的模型输入/输出长度预算。
- 做有限真实模型验收，失败或格式不符按现有规则保留，不修补模型答案或更改分数。
- 当前实例的合同标记要求集合完全匹配；增加任务必须实现受控的注册表升级，只允许
  新增且保持旧合同指纹不变，保留原账号、历史和旧排行榜，不能直接覆盖标记或重建旧库。
- 沿用单个Qwen9B服务，扩展任务不等于为每类启动一个模型进程；先测启动开销和串行
  队列等待，避免新增任务后大量排队超时。

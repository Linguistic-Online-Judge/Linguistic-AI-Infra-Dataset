# 请求级执行器：持续准入与共享健康状态

## 完成范围

`RequestSubmissionExecutor.run()`现在可以持续认领作业。后到作业不再等待整轮结束，
只要活跃作业名额空出，就能加入请求级调度。原`run_round()`仍保留用于有限轮次校准。
两者复用同一套预检、租约核验、条件成绩发布和队列回执处理。

这是**隔离执行组件**，尚未接入学校常驻服务。当前证据来自可控模型替身和真实
PostgreSQL/Redis链路，不是新的Qwen速度或评分可比性结果。

## 生命周期和内存保留

- 单个协调线程负责认领、准备作业和结算，独立请求线程执行样本。认领上下文先登记，
  再交给调度器；结算回调在调度锁外运行，并等待该作业在途请求全部结束。
- `max_jobs`限制同时保留的作业，默认4、允许1–32，不限制整个进程累计处理数量。
  超过当前容量的作业继续留在原持久队列，原提交期限持续流逝。
- 成绩条件写入、回执处理完成后，释放该作业的输入、样本结果和认领上下文。
  失败重试也先完成原有状态转换，再释放旧尝试；不保存永久的“见过的提交ID”集合。
  合法重试由数据库尝试号、租约和原重试合同保护，不能靠内存历史决定是否重发。
- `history_limit`默认256，最近结算摘要与请求派发顺序分别使用有界队列。
  持续模式返回分类计数、最近摘要和保留数量，不返回所有历史prompt或完整成绩。
  底层调度器独立使用时的派发历史默认4096条。
- 这些是对象数量和历史条数界限，不是进程物理内存的硬上限；语料缓存仍有自己的
  16条/8MiB编码载荷限制。没有改变数据库结果保留规则。
- 每次协调最多观察一条队列消息，观察间隔至少50毫秒，空闲调度等待最多100毫秒。
  路由轮转避免单一繁忙用户导致无间隔重取；多任务路由扫描、准备和逐样本数据库观察
  的实际延迟仍须单独测量。本轮单路由fixture不证明70任务下的准入延迟。

持续执行必须传入显式`model_healthy`观察函数，例如已核验模型对应的
`LocalModelProbe.healthy`。同一个执行器不能并行运行两个生命周期；持续模式退出后
不能在该对象上重新运行。操作者仍须在完整生命周期持有`executor_lock`。

## 健康、故障与停止

同进程组合可将`executor.availability`传给`create_app(runtime_probe=...)`，并用于
就绪观察；队列认领和样本派发使用同一健康来源。未运行、已退出、停止认领或故障时，
提交入口不可用。作业名额暂满不等于模型故障，正常提交仍可按原规则排队。

| 状态 | 新提交/队列认领 | 已认领作业的新样本 | 已发送请求 |
| --- | --- | --- | --- |
| 健康运行 | 允许，受原合同和活跃容量限制 | 正常分配 | 接收完整响应 |
| 模型健康暂时异常 | 暂停 | 暂停，期限继续检查 | 等待确认结束 |
| 正常停止 | 停止 | 继续排空，仍受健康与原期限限制 | 等待确认结束 |
| 调度故障或未知终止 | 阻断 | 阻断 | 排空可确认的调用，保留未知证据 |

健康探针失败可以随健康恢复解除；请求未知终止、账本读写故障、调度错误或结算存储
异常不能因模型健康恢复而自动解除。`dispatch_faulted`是本进程内无阻塞故障观察，
实际发送和认领仍经过持久账本检查。读取失败后，本生命周期停止派发，已在途请求
确认返回也保留待核实记录；启动残留仍要求原整组恢复证据。

正常停止发生在预检期间时，该作业已被认领，因此仍加入排空集合；后来未认领的
作业留在队列。健康暂停不会冻结或延长原绝对期限。回调存储异常会关闭健康状态并
停止派发，等已发调用结束；未结算的其他认领交由原租约/回执流程处理。

这些检查是有时间间隔的观察，不是模型永远健康的保证，也不能代替运行身份核验。
当前共享状态仅在同进程内有效；独立生产API与执行进程之间的就绪传播尚需部署设计。

## 验证结果（2026-09-22）

### 本地

- 一份慢作业请求保持在途，随后逐个加入6份不同prompt的完整50样本作业；6份均在
  慢作业结束前完成。累计7份、350请求，超出同时活跃上限，完成后上下文保留为0；
  测试设置的两类历史上限均为3。
- 模型不健康时不认领；恢复后开始执行；处理中再次失活，只排空已发请求，未发送
  样本暂停，恢复后共100请求完成两份作业，没有重放。
- 健康暂停仍触发原期限失败，没有模型调用或补零成绩。
- 预检期间停止仍完成已认领50样本，后续作业保持排队。
- 未知传输错误、已确认结束的内部协议错误均关闭共享健康，并等待在途同伴结束。
  未知终止保留持久阻断；协议错误不伪造未知请求记录。
- 成绩提交后回执连接失败，成绩仍持久存在，健康关闭；已有重投递保护继续覆盖。
- 账本读写失败、启动残留、完整恢复与正常在途状态的故障标记分别验证。

完整本地回归：**808通过、40项环境相关跳过，404.62秒**；静态检查通过。
本机跳过项不是通过证据，真实服务正向流程另有下面的学校验收。

## 后续验收

下一阶段需要不同任务路由、更多到达时序和真实Qwen的集成端到端测量，并确定课程
可接受的评分可比性标准。此前请求层德语约155秒的结果不能当成本轮集成性能。
30人同时提交、每份完整50样本、全部最终成绩50秒返回的目标仍未达到。

生产入口、跨进程健康传播、监督运行和部署回滚仍待完成；新的模型重启或应用维护
须另获维护窗口授权。本轮没有部署学校应用或修改模型服务。

# 产品与界面工程化审查

本文保留界面改版前的审查过程。三页结构、品牌样式、本人提示词读取与复用现已
交付并同步学校8090；当前下一阶段以 `SYSTEM_ENGINEERING_PLAN.md` 为准。

## 范围与结论

本轮是当前源码、运行设计和公开参考页面的审查，不是新一轮运行验收，也没有重做
界面或部署。18种语言和固定 Qwen3.5-9B 是既定范围，不能通过减少语言来降低界面密度。

平台已有真实账号、18语言浏览器评测、结果与排行榜、教学管理等闭环。下一阶段的
主要缺口是产品信息层级、实验复用、可重复交付及运行可靠性。过去把太多实现说明和
安全边界解释直接放到学生界面，应改为按用户目标分层呈现。

本轮参考链接已取得公开页面内容：

- 力扣题目页：https://leetcode.cn/problems/two-sum/description/
- Kattis 题目目录：https://open.kattis.com/problems
- Notion 帮助中心：https://www.notion.com/zh-cn/help
- Linear 文档：https://linear.app/docs
- MDN 学习区：https://developer.mozilla.org/zh-CN/docs/Learn_web_development

这些是成熟产品的结构参考，不是其源代码全部由人手工编写的证明。公开页面可供用户
选择方向；完整产品操作可能需要账号。Exercism 的自动读取被拒绝，两个尝试的深层
AtCoder/Linear 链接失效，因此不作为本轮已核实的选择入口。

## 已核实的工程缺口

| 领域 | 代码事实 | 下一步动作 |
| --- | --- | --- |
| 信息架构 | `web/index.html` 同时放目录、说明、编辑器、结果、排行榜和开发工具 | 分离目录、练习、结果、排行榜、管理；默认围绕一个主要操作 |
| 私人实验复用 | `OwnerSubmissionRecord` 与历史接口只返回记录摘要，结果返回提示词哈希；浏览器草稿只在内存 | 增加仅本人可读的原提示词和“复制为新评测”，再设计持久草稿；不把答案混入接口 |
| 启动与运行 | 双击脚本和SSH窗口决定访问能否成立，服务器进程并非已完成监督运行 | 启动入口先诊断连接、网页和评测执行器；状态可理解，日志可定位，恢复有明确步骤 |
| 队列容量 | 22个任务队列串行消费，执行合同的总期限含排队时间 | 测量双用户/突发提交下等待和执行耗时，再确定等待、执行预算及准入策略；不能凭队列容量声称并发容量 |
| 自动检查 | 工作流仅安装和运行Python检查；未配置浏览器检查，未设置管理员PG测试专用变量 | 加入前端/浏览器任务及数据库参数覆盖，明确哪些检查可以不下载大数据、哪些必须启用实际服务 |
| 版本交付 | 已有工作树快照打包，但重要源码仍未提交；旧运行快照与当前代码不同 | 从明确Git版本生成构件，附配置/依赖清单，在干净环境验证；main可用，不强制测试分支 |
| 文档状态 | 路线图顶部有18语言浏览器通过记录，后面仍保留“浏览器到Qwen待验收”等历史描述 | 单独维护当前能力矩阵，历史记录移入日志；区分已实现、已验证、正在运行、待发布 |
| 账号与邮件 | 开发收件箱共享；生产邮件是有界、非持久化进程队列 | 内测期间保留明确的独立调试入口；对外前接实际投递和故障恢复，不把隐藏入口当作权限控制 |
| 模型输出质量 | 已记录18项任务完成，但部分语言格式有效率很低 | 区分平台故障、格式不符、标注错误；用公开练习数据分析模板、长度预算和输出协议，保留原始评分规则 |

具体依据：`src/linguistic_oj/web/index.html`、`web/assets/app.js`、`api.py`、
`submission_store.py`、`qwen_development.py`、`auth_mail.py`、
`.github/workflows/python-quality.yml`、`tests/test_admin_store.py`。

## 建议的信息结构

| 页面/区域 | 用户的主要目标 | 默认内容 | 次要内容 |
| --- | --- | --- | --- |
| 任务目录 | 找一道要做的任务 | 语言/任务筛选、简短列表、可用状态、进入任务 | 来源、精确版本和完整指标说明 |
| 练习页 | 读懂任务并提交提示词 | 标题、一段短说明、一个正确示例、编辑器、一个提交按钮 | 完整标签表、JSON Schema、详细限制、来源许可 |
| 评测详情 | 理解这次结果并继续改进 | 状态、主分数、格式有效情况、本人提示词、再次编辑 | 其他指标、错误类别和可复现信息 |
| 我的评测 | 找到并复用自己的实验 | 任务、时间、状态、分数、查看/复制 | 筛选和同条件两次比较 |
| 排行榜 | 查看同条件下的排名 | 已选任务/版本、名次、昵称、成绩 | 比较规则和技术标识；不能混排不同评测身份 |
| 教学管理 | 编辑并发布教学内容 | 内容编辑、草稿/发布状态、保存和预览 | 来源/评分只读信息、发布动作、提交开关分组 |
| 开发工具 | 开发者检查环境和邮件 | 单独入口，非学生页首屏内容 | 原始诊断和运行说明 |

页面可使用独立路径或明确的页面级路由，不要求为了拆页面而换成另一前端框架。
HTML/CSS/JavaScript 足以实现；如重构，可按页面与职责组织原生模块，逐步减少共享
全局状态。不能在视觉重做时重写已经验证的评分器、账号权限和幂等语义。

练习页推荐仅保留两块主内容，目录与排行移出常驻两侧：

```text
任务 / 我的评测 / 排行榜                         账户
返回任务    英语 · 通用词性
--------------------------------------------------
说明 | 示例 | 评分              提示词     选择模板
短说明                         编辑区域
一个输入输出例子               …
更多任务信息                   提交评测
```

新手阅读型也可先显示单列说明，再进入编辑；用户先选择方向，再做三张灰度线框图，
不要立即写完整CSS后再让用户推翻。18语言保留在目录筛选和列表，不需要常驻装饰色带。

## 文案盘点与审查

受众是语言学学习者和研究者，不要求具备Web开发知识。按清晰、简洁、行动导向、
一致性和状态准确性审查。表内重写是建议，不代表已部署。

| 内容位置 | 严重度 | 建议 |
| --- | --- | --- |
| 多语装饰带、环境横幅、目录状态、调试工具连续占据顶部 | 高 | 去掉装饰带；环境用一个小标记表达；调试工具移至独立入口 |
| 目录与编辑器与排行榜三栏同屏 | 高 | 先选任务，再进入练习；排行榜移至单独页/标签 |
| 任务状态长说明重复“可提交”徽标 | 中 | 正常时只留“可提交”，异常时说明具体原因及下一步 |
| 教学说明、公开示例前的多句免责声明 | 中 | 一个明确的“公开练习示例”标题；必要边界放帮助说明，不每次重复 |
| 编辑器前的JSON全称和多段方法解释 | 高 | 默认一句“编写指导模型完成任务的提示词”；格式保留示例，术语解释按需展开 |
| “你的实验变量”“先读任务，再写指令”等多层小标题 | 中 | 合并成“任务说明”和“提示词”，删除不增加信息的小标题 |
| 字节/编码/模型词元长段解释 | 中 | 保留简短长度计数；超限时给具体提示，详细技术规则放“输入限制” |
| 多次重复“仅返回实际记录”“不会捏造排名” | 中 | 删除工程自证式文案；正常展示数据，无数据时提供明确空状态 |
| 注册登录介绍Cookie和脚本是否保存令牌 | 高 | 从表单移除实现解释；注册只指导填什么，成功状态指明下一步 |
| 未提交时就出现完整结果占位区 | 中 | 提交后再出现进度/结果，或进入结果页；空状态仅在专门记录页保留 |
| 评测失败与错误码 | 高 | 优先说明用户是否应修改提示词还是稍后重试；代码和细节折叠，不暴露内部异常 |
| 关闭页面、重试幂等、状态同步的长通知 | 中 | 主状态简短且以接口实际状态为准；必要解释首次操作时提示，保留“查看进度”入口 |
| 管理页16KiB/Unicode/HTML解析技术说明 | 中 | “填写学生会看到的教学内容”；限制在字段旁或超限时显示，规则文档另设入口 |
| 密码与昵称提示 | 低 | 保留已简化的8位起步和昵称要求，不为视觉重做变更账号规则 |
| 来源许可、评分规则、模型模式 | 保留 | 不能为了减字完全删除；保持可找到的入口，必要状态用短标签表达 |

可用文案示例：

| 现有表达 | 建议表达/位置 |
| --- | --- |
| 此任务允许提交且已配置评测服务……实际提交仍以服务端检查为准 | 正常状态：可提交；错误发生时再说明原因 |
| 提示词就是给模型的任务指令，会原样应用于每个样本…… | 编写指导模型完成任务的提示词。 |
| 零样本……少样本……按钮使用上方同一教学版本…… | 下拉按钮“选择模板”，在菜单或帮助中解释两种方法 |
| 登录状态由同站安全Cookie保存，脚本不存储登录令牌 | 从普通登录表单移除，保留在开发/隐私说明 |
| 整个保存请求不超过16KiB…… | 超限时：“内容过长，请缩短后保存。”，并保留可访问的详细限制 |

已有做得好的部分应保留：真实状态反馈、明确提交动作、匿名目录、可操作的重试入口、
所有者隔离、模板显式载入、暂停不删除历史、键盘焦点和窄屏基础。

一致性要求：统一使用“任务、提示词、提交评测、我的评测、教学管理”。评分结果不能
把“格式有效”改写成“答对”。发布教学内容与开放评测不是同一动作，不能用减字把
两者混淆。面向开发者的沟通术语规则不意味着要在每个按钮旁写英文全称。

最优先的三项文案改进：精简首屏横幅与状态文字；移走登录表单中的实现原理；
把编辑器前的多段解释压成一条指引加按需帮助。

## 可供选择的设计方向

| 方向 | 参考 | 对本平台的适配 |
| --- | --- | --- |
| A 简洁练习型（推荐） | 力扣题目页的描述/编辑区组织 | 独立目录，进入后两栏专注练习；不复制题解社区、会员、竞赛等无关功能 |
| B 阅读教学型 | Notion帮助中心、MDN学习内容 | 宽松单列、清楚标题与示例；阅读后进入练习，适合新手 |
| C 极简工具型 | Linear Docs的导航、分组及产品说明 | 低装饰、弱分隔、紧凑工具栏，适合研究者反复操作；不照搬营销首页 |
| D 传统评测型 | Kattis题目目录 | 简单表格、直接进入任务；只保留必要列，不复制排行榜统计列堆满首屏 |

视觉建议仍待选择：浅色背景、少量强调色、清晰的字号/间距体系；默认少量内容，
避免以压小字体或把所有说明换成图标来假装获得留白。真正的呼吸感来自减少同时
出现的任务和信息，而不是单纯把空白加大。

## 阶段与验收

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| 0 范围与设计方向 | 用户选择参考方向；目录、练习、结果三张灰度线框；当前能力矩阵 | 不改18语言/模型/账号规则；主操作与次要信息位置明确 |
| 1 前端信息架构 | 分页/标签、独立开发工具入口、精简文案、统一组件 | 默认练习视图可找到任务目标、编辑器和提交按钮；排行不抢占编辑空间；键盘和移动端可完成流程 |
| 2 实验复用 | 本人提示词查看、复制为新评测、持久草稿、同条件两条记录比较 | 刷新不丢已保存草稿；他人不可读；复制不自动执行；不同评测身份不混排 |
| 3 工程交付 | 明确main或既有分支流程、干净环境安装、分层自动检查、稳定构件与配置 | 同学按文档从同一版本启动；核心检查不意外跳过；不上传数据库/凭据；模型验收不在每次前端提交时跑900样本 |
| 4 运行可靠性 | 启动诊断、受控监督、队列预算与并发验证、备份恢复演练 | 能分清隧道、网页、队列、模型故障；重启不丢已保存记录；不盲目重试未确认终止的推理 |
| 5 对外准备（后续） | 真邮箱、关闭测试收件箱、数据权利、HTTPS与入口、旧账户绑定和容量 | 与当前开发者测试分别验收，不以页面漂亮或测试数量代替上线条件 |

阶段1的页面工作与阶段3的自动检查可并行，但不要同时改评分语义、数据库所有者边界
和整个前端框架。保留现有通过测试的接口与业务规则，通过增量修改控制回归范围。

新用户可用性验收建议：让同学不看开发文档独立寻找任务、提交并查看结果，记录卡住
的位置、完成时间和错误。目标是进入页面后很快知道下一步，不把“用户多读说明”当作
修复方案。18语言内容需同时考虑中文界面、阿拉伯语/希伯来语例子的双向文本和实际
标签规范；教学样例应由具备语言学背景的人审核。

# 请求级调度与提交持久化的隔离接入

## 1. 本轮完成内容

`request_submission_executor.py`将已验证的请求级调度接到既有提交记录、outbox、队列、
数据库认领、租约和成绩发布流程。模型仍使用显式本地HTTP替身；本轮没有调用学校Qwen、
重启服务或部署新应用，也没有更改样本数、prompt、评分及重试合同。

这是**有限认领轮次的隔离执行器**，不是常驻生产入口：每轮先认领有限数量作业，再
共享请求槽位执行；各作业完成后立即结算，不必等其他作业完成。未被认领的作业留在
队列，外层调用者可以执行下一轮。持续运行时的新到作业还不会直接插入已经启动的
轮次；这一限制不同于底层调度器支持的动态添加能力，需要后续分别验证。

## 2. 认领与租约保护

- 复用原worker的消息路由校验、数据库认领、每用户运行限制、过期处理和队列回执。
  认领门闩仍与请求账本共用故障协调锁；已阻断时不取走新消息。
- 明确区分队列为空、暂不可认领和成功认领；同轮再次遇到同一消息就停止该路由扫描，
  避免同一用户忙碌时不断nack造成空转。
- 每轮认领量有界；样本预检、数据完整性和原绝对期限校验完成后才交给调度器。
  采用的是数据库已有`deadline_at`，不会从调度开始重新计算期限。
- SQLite/PostgreSQL新增只读`claim_is_current`，核对用户、尝试编号、租约令牌、截止
  时间、租约期限以及合同/评测身份。PostgreSQL使用数据库自身时间。
- 每次准备发送样本时检查认领是否仍有效。该检查是一份观察，不能代替最终事务保护，
  也不能保证检查之后租约绝不会改变。没有增加续租或延长期限行为。

这些方法使用既有列，数据库仍为schema v4，无模式迁移。

## 3. 完整成绩与回执

`SampleScheduler.run(on_terminal=...)`在作业完成或失败且其在途请求全部结束后，
调用一次结算回调。回调在调度锁外执行，避免持锁进行数据库/队列操作。

成功路径：

1. 必须拥有完整样本结果，且样本数与该合同清单一致。
2. 调用原`contract.owner_result`绑定本次prompt摘要。
3. 调用原`complete_success`，由数据库在事务内再次检查尝试编号、租约及期限。
4. 成绩落库成功后才确认队列回执。

如果租约失效或写入时已经过期，旧worker不能覆盖其他执行者的状态，也不能发布
迟到成绩。内存中算出聚合结果不等于数据库已接受；对用户展示仍以持久化结果为准。

成绩已提交但ACK失败时，不重新运行模型。消息重投递后，原认领逻辑识别已完成提交，
直接处理回执。旧回执也不能删除新接收者的回执。

## 4. 失败与重试

- 已确认结束的provider错误仍按原合同的重试码、最大尝试次数处理。
- 重试或终态写入要等待该作业已发出的同批请求结束，避免新尝试与旧请求重叠。
- 任何未确认请求使共享账本阻断；不能通过本轮适配层绕过恢复或自动重发。
- 数据、预检、期限或租约问题不转化成零分样本；未完整完成的作业没有成绩。
- 结算回调出现存储异常时，停止新的样本派发并排空已发调用。没有自动重试结果
  写入；后续依据真实数据库状态、租约和回执处理，不猜测一次失败写入是否已提交。

底层快照新增安全的失败代码/是否确认终止的信息，不保存异常正文、学生prompt或
原始模型答案。既有实验脚本仍可不传结算回调，保持原请求层用途。

## 5. 验证证据

### 本地故障测试

- 两用户、不同prompt、完整50样本；同一用户的第二份作业留待下一轮。
- 快作业完整成绩先入库，慢作业仍在执行时不阻挡快作业结果。
- 发送中途撤销租约：已发请求排空，剩余样本不再调用模型，旧回执不能ACK新接收者。
- 最后一次观察有效、事务写入前租约变化：聚合结果被条件写入拒绝。
- 提交时已过期及写入时数据库时间已过期：失败并保留原期限，没有伪造成绩。
- 已确认传输错误：等待同作业在途调用结束后重试，尝试号增加但期限不变。
  未确认错误：没有重试、没有成绩，后续执行被账本阻断。
- 成绩提交后ACK连接失败，再次投递没有重复模型调用或重复成绩。

本地完整回归797通过/37环境相关跳过。早先命令时限不足导致测试中断，分组检查没有
发现死锁；延长观察时限后全套372.68秒完成。新增的PostgreSQL负向租约测试由CI执行，
不能将本机跳过计为已通过。

## 6. 当前边界与后续

本轮证明的是请求级调度与持久提交链路的关联、结果和故障保护。每次样本发送前的
数据库观察会增加开销，需要在真实模型全链路中测量，不能直接套用此前请求层的
3.3倍提速。前端显示、真实模型评分可比性和30人50秒仍未完成相应验收。

新组件仍使用实验provider，正式运行核验会拒绝；没有启用生产常驻入口或改写旧合同。
剩余工作包括持续准入/健康联动、更多到达时序与任务组合、真实模型集成和部署回滚
核验。先前维护窗口已经结束，本轮未复用其授权修改学校服务。
